> 基于项目计划书，拆解为 UrhoX 引擎可落地的技术任务
>
> 创建时间: 2026-05-17
> 更新时间: 2026-06-19
> 状态: **v1.1.0 开发完成，测试准备阶段**

---

## 技术选型概要

| 维度 | 方案 |
|------|------|
| 引擎 | UrhoX (Lua 5.4) |
| 架构 | 多人 C/S（服务端权威） |
| UI 系统 | urhox-libs/UI (Yoga Flexbox) + UIUtils |
| 网络 | UrhoX 内置多人框架 (match_info 房间制) |
| 存储 | serverCloud（服务端云变量） + clientCloud（客户端） |
| 商业化 | 广告（UrhoX 广告 SDK） |
| 屏幕方向 | 横屏 (landscape) — 提供更广阔的竞拍视野 |

## 阶段一：核心原型 (Prototype) ✅

**目标**: 4 人联机暗拍核心循环可玩

### 任务 1.1 — 项目初始化与框架搭建 ✅

- [x] 基于 `scaffold-3d-scene.lua` 创建项目结构
- [x] 配置多人模式 (`multiplayer.enabled = true, max_players = 4, match_info`)
- [x] 建立模块化目录结构

### 任务 1.2 — 暗拍核心逻辑（服务端权威） ✅

- [x] **出价系统 (BidSystem)**
  - 玩家在时限内提交出价
  - 服务端独立保存所有出价，揭晓前客户端不可见
  - 出价校验：范围合法、余额充足、时限内

- [x] **回合管理 (RoundManager)**
  - 默认 5 轮制
  - 速胜窗口：第 1-4 轮如果第一名出价分别以 200%/160%/140%/120% 碾压第二名，立即结束
  - 第 5 轮价高者得，相同则加赛
  - 每轮状态机：`准备 → 出价中 → 结算 → 下一轮/结束`

- [x] **信息提示系统**
  - 每轮结束后仅显示模糊信息（"领先"、"接近"、"落后"）
  - 不泄露具体金额

### 任务 1.3 — 基础 UI ✅

- [x] **出价面板 (BidPanel)** — 金额输入 + 确认按钮 + 倒计时
- [x] **HUD** — 当前轮次、剩余资金、玩家列表（头像+状态指示）
- [x] **结算面板** — 胜负显示、出价对比揭晓

### 任务 1.4 — 基础网络同步 ✅

- [x] 定义消息协议 (Protocol.lua)
- [x] 服务端处理逻辑：收集出价 → 判定 → 广播结果
- [x] 客户端处理逻辑：发送出价 → 等待结果 → 更新 UI

## 关键技术风险

| 风险 | 影响 | 缓解方案 |
|------|------|---------|
| 暗拍信息泄露 | 破坏核心玩法 | 客户端不保存他人出价，服务端权威 ✅ |
| 服务器并发瓶颈 | 匹配失败/延迟高 | match_info 配置优化 + AI 填充 ✅ |
| 经济系统通胀 | 游戏寿命缩短 | serverCloud 事务保证原子性，严控产出 ✅ |
| 作弊/外挂 | 公平性受损 | 服务端校验所有关键逻辑 + AntiCheat 增强检测 ✅ |
| 玩家留存率低 | 游戏活跃度不足 | 成就系统 + 每日任务 + 新手引导增强 ✅ |
