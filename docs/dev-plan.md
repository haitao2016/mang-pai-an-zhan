# 《盲拍暗战》技术开发计划

> 基于项目计划书，拆解为 UrhoX 引擎可落地的技术任务
>
> 创建时间: 2026-05-17
> 状态: 待开发

---

## 技术选型概要

| 维度 | 方案 |
|------|------|
| 引擎 | UrhoX (Lua 5.4) |
| 架构 | 多人 C/S（服务端权威） |
| UI 系统 | urhox-libs/UI (Yoga Flexbox) |
| 网络 | UrhoX 内置多人框架 (match_info 房间制) |
| 存储 | serverCloud（服务端云变量） + clientCloud（客户端） |
| 商业化 | 广告（UrhoX 广告 SDK） |
| 屏幕方向 | 竖屏 (portrait) — 适合移动端竞拍操作 |

## 阶段一：核心原型 (Prototype)

**目标**: 4 人联机暗拍核心循环可玩

### 任务 1.1 — 项目初始化与框架搭建

- [ ] 基于 `scaffold-3d-scene.lua` 创建项目结构
- [ ] 配置多人模式 (`multiplayer.enabled = true, max_players = 4, match_info`)
- [ ] 建立模块化目录结构：

```
scripts/
├── main.lua                # 入口（单机/多人分流）
├── client_main.lua         # 客户端入口
├── server_main.lua         # 服务端入口
├── Config.lua              # 全局配置（轮数、速胜倍率等）
├── Game/
│   ├── AuctionManager.lua  # 竞拍核心逻辑
│   ├── BidSystem.lua       # 出价系统
│   ├── RoundManager.lua    # 回合管理（5轮制+速胜窗口）
│   ├── ItemPool.lua        # 藏品池
│   └── RevealSystem.lua    # 开箱逐件揭示
├── Network/
│   ├── Client.lua          # 客户端网络逻辑
│   ├── Server.lua          # 服务端权威逻辑
│   └── Protocol.lua        # 消息协议定义
├── UI/
│   ├── HUD.lua             # 游戏内 HUD（余额、轮次、计时）
│   ├── BidPanel.lua        # 出价面板
│   ├── ResultPanel.lua     # 结算面板
│   ├── RevealPanel.lua     # 开箱展示面板
│   └── LobbyUI.lua        # 大厅/匹配 UI
└── Utils/
    └── Helper.lua          # 工具函数
```

### 任务 1.2 — 暗拍核心逻辑（服务端权威）

- [ ] **出价系统 (BidSystem)**
  - 玩家在时限内提交出价（金额加密上传）
  - 服务端独立保存所有出价，揭晓前客户端不可见
  - 出价校验：范围合法、余额充足、时限内

- [ ] **回合管理 (RoundManager)**
  - 默认 5 轮制
  - 速胜窗口：第 1-4 轮如果第一名出价分别以 200%/160%/140%/120% 碾压第二名，立即结束
  - 第 5 轮价高者得，相同则加赛
  - 每轮状态机：`准备 → 出价中 → 结算 → 下一轮/结束`

- [ ] **信息提示系统**
  - 每轮结束后仅显示模糊信息（"领先"、"接近"、"落后"）
  - 不泄露具体金额

### 任务 1.3 — 基础 UI

- [ ] **出价面板 (BidPanel)** — 金额输入 + 确认按钮 + 倒计时
- [ ] **HUD** — 当前轮次、剩余资金、玩家列表（头像+状态指示）
- [ ] **结算面板** — 胜负显示、出价对比揭晓

### 任务 1.4 — 基础网络同步

- [ ] 定义消息协议 (Protocol.lua)：
  - `C2S_BID` — 客户端提交出价
  - `S2C_ROUND_START` — 新回合开始
  - `S2C_ROUND_RESULT` — 回合结果（模糊信息）
  - `S2C_GAME_END` — 比赛结束 + 完整揭晓
- [ ] 服务端处理逻辑：收集出价 → 判定 → 广播结果
- [ ] 客户端处理逻辑：发送出价 → 等待结果 → 更新 UI

## 阶段二：体验完善 (Alpha)

**目标**: 开箱体验 + 角色技能 + 藏品系统

### 任务 2.1 — 开箱揭示系统 (RevealSystem)

- [ ] 获胜后进入开箱流程
- [ ] 藏品逐件从迷雾中显现（3D 模型 + 旋转展示 + 粒子特效）
- [ ] 稀有度分级视觉反馈（普通/稀有/史诗/传说，不同光效）
- [ ] 总价值揭晓 + 盈亏计算

### 任务 2.2 — 角色技能系统

- [ ] **技能类型设计**（初始 8 角色，每人 1 主动技能 + 1 被动）：
  - 情报揭示类：窥探对手上轮出价、预知藏品部分价值
  - 价值标记类：标记物品真实价值区间
  - 干扰信号类：向对手发送虚假信息提示
- [ ] 技能 CD / 使用次数限制
- [ ] 服务端校验技能合法性

### 任务 2.3 — 藏品系统 (ItemPool)

- [ ] 藏品数据结构：名称、描述、稀有度、价值区间、3D 模型引用
- [ ] 藏品池配置（JSON 数据驱动）
- [ ] 初始 300 个藏品数据
- [ ] 随机抽取算法（保证每箱总价值在合理区间，稀有度加权）

### 任务 2.4 — 拍卖厅/地图系统

- [ ] 4 个不同主题拍卖厅（入场门槛不同）
- [ ] 3D 场景搭建（简单场景 + 环境光）
- [ ] 拍卖厅选择 UI

## 关键技术风险

| 风险 | 影响 | 缓解方案 |
|------|------|---------|
| 暗拍信息泄露 | 破坏核心玩法 | 客户端不保存他人出价，服务端权威 |
| 服务器并发瓶颈 | 匹配失败/延迟高 | match_info 配置优化 + AI 填充 |
| 经济系统通胀 | 游戏寿命缩短 | serverCloud 事务保证原子性，严控产出 |
| 作弊/外挂 | 公平性受损 | 服务端校验所有关键逻辑 |

## 当前开发优先级

```
高优先级（阶段一必须完成）:
  ├── 项目初始化 + 多人框架
  ├── 暗拍核心逻辑（出价/回合/判定）
  ├── 基础 UI（出价面板/HUD/结算）
  └── 基础网络同步

中优先级（阶段二）:
  ├── 开箱揭示系统
  ├── 角色技能系统
  └── 藏品数据系统

后续优先级:
  ├── 匹配系统
  ├── 收藏馆
  ├── 社交系统
  └── 商业化
```
